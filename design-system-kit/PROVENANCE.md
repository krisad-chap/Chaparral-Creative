# About this folder

Generated by [Claude Design](https://claude.ai/design) from this repository, then committed back. It is a **derived layer**, not the source.

## What's canonical

`../brand/` is the source of truth. If a value disagrees between here and there, `brand/` wins.

| This folder | Canonical original | Relationship |
|---|---|---|
| `tokens/colors.css`, `typography.css`, `layout.css`, `base.css` | `brand/tokens.css` | Split into separate files. Same values. |
| `tokens/components.css` | `brand/components.css` | **Byte-identical copy.** Edit `brand/components.css`, then re-sync. |
| `assets/logo-*.svg` | `brand/assets/logo-*.svg` | Same artwork, path data verified identical. |
| `readme.md` (voice, visual rules) | `brand/guidelines.md` | Restated. `brand/guidelines.md` is authoritative. |

**Do not edit the duplicated files here directly.** Change `brand/`, then regenerate this folder from Claude Design. Two copies of a token file that drift apart is worse than having one.

## What's genuinely new here

Not in `brand/` — this is the reason the folder exists:

- `components/` — React primitives (`.jsx`) with TypeScript definitions (`.d.ts`) and per-component usage notes (`.prompt.md`). Built on the `.cc-` class contracts, so they're a layer over the CSS, not a replacement.
- `ui_kits/website/` — working Home, Service, Work and Contact page components, plus a click-through `index.html`.
- `guidelines/*.card.html` — the visual foundations as individual reference cards.
- `SKILL.md` — makes this folder installable as a Claude skill, so future sessions can produce on-brand work without re-explaining the brand.
- `_ds_bundle.js` — the components compiled into one file, so `ui_kits/website/index.html` runs in a browser with no build step.
